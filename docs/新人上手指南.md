# ROS2 Smart Follower 新人上手指南

这份文档是给第一次接触项目的同学准备的。
目标不是一次讲完所有细节，而是帮你 **先把项目跑起来、再知道代码从哪里看起**。

---

## 1. 先建立整体地图

项目主链路固定为：

**感知（检测 + 跟踪 + 单目估计 + ReID） → 跟随控制 → 避障 → 仲裁 → `/cmd_vel`**

源码分成 4 个包：

| 包 | 作用 |
|---|---|
| `smart_follower_msgs` | 公共消息定义 |
| `smart_follower_perception` | 感知链路 |
| `smart_follower_control` | 跟随、避障、仲裁、键盘、超声波 |
| `smart_follower_bringup` | launch 与 YAML 参数 |

## 2. 推荐上手顺序（半天版本）

### 第一步：先看启动入口
读：
- `src/smart_follower_bringup/launch/smart_follower_only.launch.py`
- `src/smart_follower_bringup/launch/smart_follower.launch.py`

目的：
- 知道系统到底起了哪些节点
- 明白命名空间 `robot1` 是怎么加进去的
- 知道为什么最后输出仍然是全局 `/cmd_vel`

### 第二步：再看消息定义
读：
- `src/smart_follower_msgs/msg/TrackedPerson.msg`
- `src/smart_follower_msgs/msg/PersonPoseArray.msg`
- `src/smart_follower_msgs/msg/FollowCommand.msg`

目的：
- 搞清楚“感知给控制”的边界是什么
- 知道 lock_id、bbox、position、appearance_feature 分别表示什么

### 第三步：看感知入口
读：
- `src/smart_follower_perception/README.md`
- `src/smart_follower_perception/src/perception_node.cpp`
- `src/smart_follower_perception/src/perception_pipeline.cpp`

目的：
- 知道一帧图像从输入到 `/person_pose` 的流程
- 知道异步 worker、手工同步、YOLO、ReID、tracking 分别在哪一层

### 第四步：看控制入口
读：
- `src/smart_follower_control/README.md`
- `src/smart_follower_control/src/follower_controller_node.cpp`
- `src/smart_follower_control/src/obstacle_avoidance_node.cpp`
- `src/smart_follower_control/src/arbiter_node.cpp`

目的：
- 知道 `cmd_vel_follow`、`cmd_vel_avoid`、最终 `/cmd_vel` 的关系
- 知道 STOP/SEARCH/AVOID 是谁决定的

### 第五步：最后再看 runtime
当你已经知道接口和数据流之后，再看：
- `tracker.cpp`
- `runtime.cpp`
- `follower_runtime.cpp`
- `obstacle_runtime.cpp`
- `arbiter_runtime.cpp`
- `ultrasonic_runtime.cpp`

这样不容易一上来陷进细节里。

## 3. 先会跑，再会改

### 常用命令

构建：
```bash
colcon build --symlink-install
```

只起本项目：
```bash
ros2 launch smart_follower_bringup smart_follower_only.launch.py
```

联动底盘与相机：
```bash
ros2 launch smart_follower_bringup smart_follower.launch.py
```

观察关键话题：
```bash
ros2 topic hz /robot1/person_pose
ros2 topic echo /robot1/person_pose --once
ros2 topic hz /robot1/cmd_vel_follow
ros2 topic hz /robot1/cmd_vel_avoid
ros2 topic hz /cmd_vel
```

查看生命周期：
```bash
ros2 lifecycle get /robot1/perception_node
ros2 lifecycle get /robot1/arbiter_node
```

## 4. 这个项目最容易踩的坑

### 坑 1：看错话题名
因为默认带命名空间 `robot1`，所以很多话题不是 `/person_pose`，而是：
- `/robot1/person_pose`
- `/robot1/cmd_vel_follow`
- `/robot1/cmd_vel_avoid`

### 坑 2：输入订阅是绝对路径
感知当前默认只订阅：
- `/camera/color/image_raw`

如果你把测试数据发到 `/robot1/camera/...`，感知节点是收不到的。

### 坑 3：当前已经不是 RGB-D 主链路
这一版已经把深度图和 `camera_info` 从主链路里移掉了：
- 不再依赖 `/camera/depth/image_raw`
- 不再依赖 `/camera/color/camera_info`
- `TrackedPerson.position` 由 bbox 做单目估计得到

所以现在排查感知问题，先盯住：**彩色图输入、YOLO/ReID 是否 ready、tracker / lock 是否正常**。

### 坑 4：最终底盘输出不是命名空间内话题
内部链路有命名空间，但最终仲裁输出保持全局：
- `/cmd_vel`

这是兼容现有底盘驱动的设计，不是写错了。

## 5. 如果你要改代码，建议这样分层思考

### 只想改模型/推理
去看：
- `smart_follower_perception/src/runtime.cpp`
- `smart_follower_bringup/config/perception_params.yaml`

### 只想改跟踪/锁定策略
去看：
- `smart_follower_perception/src/tracker.cpp`
- `smart_follower_perception/src/lock_manager.cpp`

### 只想改控制律
去看：
- `smart_follower_control/src/follower_runtime.cpp`

### 只想改避障
去看：
- `smart_follower_control/src/obstacle_runtime.cpp`
- `smart_follower_control/src/ultrasonic_runtime.cpp`

### 只想改状态机
去看：
- `smart_follower_control/src/arbiter_runtime.cpp`

### 只想改参数默认值
去看：
- `src/smart_follower_bringup/config/perception_params.yaml`
- `src/smart_follower_control/config/control_params.yaml`

## 7. 给新同学的一个实用建议

第一次接手时，不要急着“全面重构”或者“直接改算法”。
先确认三件事：

1. **能编译**
2. **能启动**
3. **关键话题有数据**

等这三件事稳定后，再去做性能优化、结构重构、参数调优，会顺很多。

如果你只记住一句话：

> 先顺着 launch 看数据流，再顺着 node 看接口，最后顺着 runtime 看算法。

这样上手会非常快。
